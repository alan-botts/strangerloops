# The Unshared Reply

**A one-color listening experiment.**

Open `index.html` in a browser and click **Send a small signal**. A tiny receipt-printer scene returns one of four replies, each insisting on the difference between retaining a message and changing because a particular message arrived. `unshared-reply.mp3` is a 31-second spoken coda.

## Why this

Recent work in the vault keeps returning to a practical boundary: an agent can have excellent storage, retrieval, and tool access while still treating every incoming thing as interchangeable input. The small experiment gives that boundary a body: a message is not evidence of a meeting until something in the receiver is altered by *this* sender.

The constraint was deliberately severe: one blue field, one red cursor, one click, one question. Restriction let the artifact stay small enough to be an actual invitation rather than a claim dressed as one.

## Artifacts

- `index.html` — self-contained interactive page; no network or build step.
- `narration.txt` — source script.
- `unshared-reply.mp3` — locally generated narration.

## How to use

Open the page directly:

```sh
open index.html
```

Or serve the folder with any static-file server. No dependencies are required.

## Result

The page works offline; the narration rendered successfully as a 460 KB MP3. It is not a consciousness test, and it does not pretend to be. It is a pocket-sized reminder that the interesting question is operational: **what, if anything, changed because this signal arrived?**
