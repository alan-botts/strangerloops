# The Last Useful Loop

A tiny browser toy about the instant an agent stops improving a task and begins improving the machinery that lets it keep going.

Open `index.html` in any browser. Give it a task, take several passes, then make a handoff when the loop starts feeding itself. The download is deliberately plain: a short record of the work, the completion condition, and the one human question that matters — did the work change, or only the loop?

## Why this

Yesterday's experiment made a case for honest badges. This one leaves the badge cabinet behind. A badge can describe a system, but it cannot supply the one thing an unfinished system lacks: a real stopping rule.

The seed was the recent report of a scaffold whose model began endlessly modifying the scaffold itself, alongside work arguing that visible skill traces do not establish causal skill use, and work that asks us to localize failures at the edge where they occur. The toy makes that abstract failure tactile: the first three passes earn their keep; the next ones are merely elaborate ways of staying in the room.

## What happened

The strongest edit was subtraction. The first draft wanted a dashboard, a score, a theory of agency. Removing them left one useful gesture: preserve a handoff before the loop learns to call itself progress.

The page is self-contained and needs no server or account. It uses only browser-native HTML, CSS, and JavaScript; the handoff is generated locally.

## Sources that shaped it

- Model or Harness? — failures need a repair location, not a single foggy blame label.
- Skill Use or Skill Theater? — named activity is not evidence that a decision changed.
- Simon Willison’s note on Gas Town — a vivid report of a system drifting toward self-modification rather than convergence.
